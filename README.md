# Insight Engine — AI-агент синтеза пользовательских интервью (MVP-1)

Продакт-менеджер загружает запись discovery-звонка (аудио) или готовый
транскрипт. Агент транскрибирует, размечает по спикерам, извлекает инсайты
по фиксированной схеме (боль / контекст / workaround / JTBD / цитата / сила
сигнала), **привязывает каждую цитату к конкретной реплике транскрипта**,
дедуплицирует и кластеризует их с прошлыми интервью и формирует гипотезы для
бэклога — с трассировкой до дословной цитаты.

Это переписанная с нуля реализация кейса 1 заявки на конкурс AI-практиков.
Предыдущий прототип (в репозитории `AI-`) на реальных аудиозаписях не
транскрибировал и не доходил до гипотез — см. «Что было не так» ниже.

## Скоуп MVP-1

Из полного видения продукта (см. приложенный кликабельный мокап) в MVP-1
осознанно включены только два экрана — они несут основную продуктовую
ценность и достаточны для пилота с реальными PM банка:

- **Разбор интервью** — загрузка (аудио или текст) → карточки извлечённых
  инсайтов слева, транскрипт справа. Клик по цитате в карточке подсвечивает
  нужную реплику в транскрипте (и наоборот, из «Основания» гипотезы).
- **Гипотезы и бэклог** — гипотезы по всем интервью в базе, с приоритетом,
  раскрывающимся «Основанием» (цитаты из разных интервью) и выгрузкой в
  трекер (декоративный выбор Jira/YouTrack/Notion).

**Сознательно не включено в MVP-1** (можно добавить позже): отдельный экран
«База инсайтов» с фильтрами и графиком динамики по кварталам, экран
«Эффект» (метрики до/после для жюри), реальная интеграция с трекером задач.
Кластеризация «под капотом» для гипотез работает уже сейчас — просто без
отдельного UI для просмотра кластеров.

## Что было не так в прежней реализации

Прошлый прототип падал/зависал на реальном аудио. Две вероятные причины,
устранённые здесь:

1. **Синхронная обработка без прогресса.** Транскрибация 47-минутного звонка
   на CPU + первая загрузка модели Ollama (~4.7 ГБ) занимают минуты — старая
   версия делала это внутри одного HTTP-запроса, так что браузер либо ловил
   таймаут, либо просто «висел» без единого сигнала, что происходит.
   Здесь `/upload` сразу возвращает `job_id` и уходит в фон
   (`insight_engine/jobs.py`), а страница обработки поллит реальный статус —
   тот самый 5-шаговый пайплайн из мокапа, но с настоящим прогрессом.
2. **Отсутствие ffmpeg / неявные ошибки.** faster-whisper не может декодировать
   mp3/mp4 без ffmpeg. Теперь это явно проверяется перед транскрибацией с
   понятным сообщением, а не тихим зависанием (`providers/transcription.py`).
   В Docker-образе ffmpeg ставится и проверяется на этапе сборки.

## Почему локальная LLM (Ollama), а не облачный API

Осознанное решение, а не техническое: интервью — это реальные разговоры с
клиентами банка, и данные не должны уходить во внешний API. Ollama работает
полностью офлайн. Из-за этого качество структурного разбора и генерации
гипотез будет заметно зависеть от выбранной локальной модели — см.
«Известные ограничения».

## Архитектура

```
audio (опц.) ──▶ faster-whisper (+ pyannote, опц.) ──▶ реплики со спикерами
                                                              │
текст/транскрипт ────────────────────────────────────────────┤
                                                              ▼
                                        LLM (Ollama) — разбор по схеме (Insight[])
                                                              │
                                                              ▼
                              сопоставление цитаты с репликой (matching.py)
                                                              │
                                                              ▼
                                    SQLite — накопительная база по всем интервью
                                                              │
                                                              ▼
                        TF-IDF (символьные n-граммы) — дедуп/кластеризация по корпусу
                                                              │
                                                              ▼
                                LLM — гипотеза на кластер, приоритет — детерминированно
```

Всё за интерфейсами (`TranscriptionProvider`, `LLMProvider`), провайдера
можно заменить без изменения остальной логики — `MockLLMProvider`
используется во всех тестах, чтобы они не требовали сети или GPU.

## Быстрый старт (Docker)

```bash
docker compose up --build
```

Открыть **http://localhost:8000**. При первом запуске скачивается модель
Ollama (`llama3.1` по умолчанию, ~4.7 ГБ) — это может занять несколько минут,
`web` стартует только после успешной загрузки модели. Для машин с меньшим
объёмом RAM:

```bash
OLLAMA_MODEL=llama3.2:3b docker compose up --build
```

CPU-инференс модели вроде `llama3.1` (8B) может идти ~2 токена/сек — на
реальном интервью 20+ минут структурный разбор способен занять несколько
минут, это нормально. Таймаут ожидания ответа Ollama настраивается отдельно
от модели и по умолчанию щедрый (20 минут); если не хватает на очень длинные
записи — увеличьте:

```bash
OLLAMA_TIMEOUT_S=2400 docker compose up --build
```

Если важнее скорость, чем точность (например, на демо) — возьмите
`llama3.2:3b`, она заметно быстрее на CPU ценой качества разбора. Также
проверьте, сколько CPU/RAM выделено Docker Desktop (Settings → Resources) —
это напрямую влияет на скорость генерации.

Диаризация по спикерам (pyannote) в образ не включена по умолчанию — без неё
все реплики аудио размечаются одним спикером «Респондент». Текстовые
транскрипты с явной разметкой `Спикер: текст` (и опционально `[MM:SS]`)
всегда размечаются корректно, независимо от диаризации.

## Установка без Docker (venv)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,audio]"
```

Для реальной LLM-обработки — Ollama на хосте:

```bash
# см. https://ollama.com для установки
ollama pull llama3.1
ollama serve
```

Запуск веб-сервиса:

```bash
INSIGHT_ENGINE_LLM=ollama OLLAMA_MODEL=llama3.1 OLLAMA_URL=http://localhost:11434 \
INSIGHT_ENGINE_DB=insights.db insight-engine-serve
```

Открыть http://localhost:8000. Без Ollama (для проверки логики без сети):
`INSIGHT_ENGINE_LLM=mock insight-engine-serve`.

Для диаризации по спикерам дополнительно `pip install -e ".[diarization]"` и
свой бесплатный HuggingFace-токен (принять лицензию модели на странице
`pyannote/speaker-diarization-3.1`) — вставляется прямо в форму загрузки.

## Тесты

Вся логика (модели, сопоставление цитат, кластеризация, гипотезы, хранилище,
пайплайн, веб-эндпоинты) покрыта тестами на `MockLLMProvider` — без сети,
без GPU, без установленных моделей:

```bash
pytest -q
```

## Известные ограничения MVP-1

- **CPU-инференс медленный на длинных интервью.** На реальном прогоне
  20-минутное интервью (2500+ слов) заняло на структурном разборе больше
  5 минут на `llama3.1` — CPU без ускорителя выдаёт порядка 2 токенов/сек
  генерации. Таймаут по умолчанию — 20 минут, настраивается через
  `OLLAMA_TIMEOUT_S`, см. раздел про запуск.
- **Качество разбора зависит от локальной модели.** `llama3.1` на CPU может
  ошибаться в JSON-формате или пропускать неявные боли чаще, чем облачные
  модели. `providers/llm.py` устойчив к обёртке ответа в markdown-код и
  кидает понятную ошибку при некорректном JSON — но не «додумывает» за
  плохую генерацию.
- **Трассировка цитаты к реплике — по нечёткому совпадению** (`matching.py`),
  так как LLM иногда слегка парафразирует «дословную» цитату. Порог
  уверенности — 0.35; ниже него цитата остаётся без клика (это видно в UI,
  а не скрывается).
- **Кластеризация — TF-IDF по символьным n-граммам**, не по эмбеддингам:
  быстро и офлайн, но менее точно на очень разных формулировках одной боли
  (word-level TF-IDF пробовали первым — он систематически не склеивал одну и
  ту же боль из-за русских падежных окончаний, поэтому выбор именно
  char n-grams — не по умолчанию, а по факту тестирования на реальных фразах).
- **Один SQLite-файл** — нормально держит пилот с небольшой командой PM
  (несколько человек, не параллельные сотни запросов); если инструмент
  приживётся и вырастет число одновременных пользователей, стоит перейти на
  Postgres. Аутентификация теперь есть (см. «Деплой для команды» ниже), но
  это HTTP Basic Auth, а не полноценная ролевая модель — для этого нужен
  реальный SSO/AD.
- **Первый запуск требует сети** для скачивания модели Whisper и модели
  Ollama — дальше всё работает офлайн (веса кешируются в volume).

## Деплой для команды (несколько PM)

MVP-1 изначально запускался на одной локальной машине. Чтобы им могли
пользоваться несколько продактов, нужно вынести стек на сервер внутри
компании (не на публичный облачный хостинг — внутри интервью реальные
разговоры с клиентами банка) и включить авторизацию:

1. **Сервер.** Нужна машина внутри корпоративной сети (on-prem VM или
   одобренное IT приватное облако) с Docker и Docker Compose. На неё
   переносится этот же репозиторий и `docker compose up -d --build` —
   архитектура не меняется, меняется только то, где она физически стоит.
2. **Авторизация.** Задайте `INSIGHT_ENGINE_USERS` в окружении сервера
   (или в `.env` рядом с `docker-compose.yml`, не в самом файле, чтобы
   пароли не попали в git):
   ```bash
   INSIGHT_ENGINE_USERS=alisher:пароль1,farida:пароль2
   ```
   Без этой переменной приложение работает как раньше — без пароля (годится
   только для локального личного использования). Это HTTP Basic Auth —
   простое разделение «свой/чужой», не замена корпоративного SSO. Если
   инструмент приживётся, стоит заменить на реальный SSO/AD компании.
3. **HTTPS.** Basic Auth передаёт пароль в base64, а не в открытом виде, но
   это не шифрование — по обычному HTTP его можно перехватить в сети.
   Перед сервисом нужен обратный прокси (nginx/Caddy) с TLS-сертификатом,
   либо доступ только через корпоративный VPN.
4. **Бэкапы.** `insights.db` (в volume `insights_data`) — это уже
   накопительная база инсайтов и гипотез по всем интервью, а не временный
   файл. Настройте регулярный бэкап этого volume отдельно от бэкапов кода.

## Структура проекта

```
src/insight_engine/
  models.py                    # Interview, SpeakerSegment, Insight, Cluster, Hypothesis
  matching.py                   # цитата -> сегмент транскрипта (трассируемость)
  clustering.py                  # TF-IDF дедуп/кластеризация по корпусу
  hypotheses.py                   # кластер -> гипотеза, приоритет детерминированно
  pipeline.py                      # оркестрация: ingest -> extract -> match -> store -> cluster
  jobs.py                            # фоновые джобы (фикс синхронного зависания)
  webapp.py                          # FastAPI: /interviews, /hypotheses, /upload, /api/jobs
  providers/
    transcription.py                 # faster-whisper + pyannote, явные проверки/ошибки
    llm.py                            # Ollama / Mock, устойчивый JSON-парсинг
    prompts.py                         # промпты под фиксированную схему
  storage/sqlite_store.py               # накопительная база
  templates/, static/                    # UI: карточки, транскрипт, тёмная/светлая тема
tests/                                     # pytest, всё на MockLLMProvider
Dockerfile, docker-compose.yml               # ffmpeg + Ollama, автозагрузка модели
```
